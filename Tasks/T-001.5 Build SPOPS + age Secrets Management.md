# T-001.5 Build SPOPS + age Secrets Management

## Outcome

Reproducible local env and remote dev env for secure sharing of project API / ssh keys and secrets.


## Perplexity Result

https://www.perplexity.ai/computer/tasks/02f6cf8c-bae7-416f-af41-e1693b164228

The guide and a drop-in kit are ready. Everything was built and verified end-to-end, and one finding changes the setup entirely on Big Sur.

## The Big Sur catch

The latest releases of both tools will not run on macOS 11. Both are Go programs, and Go 1.24 is the last toolchain that runs on Big Sur — Go 1.25+ requires Monterey ([Go 1.24 release notes](https://go.dev/doc/go1.24#darwin), [Go 1.25 release notes](https://go.dev/doc/go1.25#darwin), Go wiki: Darwin). I inspected the embedded Go build versions in the actual darwin binaries on the [sops](https://github.com/getsops/sops/releases) and age release pages: every newer release was built with Go 1.25+. The guide pins **sops v3.10.2** (built with Go 1.24.2) and **age v1.2.1** (Go 1.23.4), with checksum-verified manual install steps.[[github](https://github.com/FiloSottile/age/releases)][[go](https://go.dev/wiki/Darwin)]

## What's in the guide

- Manual binary installation into `~/.local/bin` with abort-on-mismatch checksum checks and Gatekeeper notes
- age key generation under a restrictive umask, with `SOPS_AGE_KEY_FILE` set explicitly
- A `.sops.yaml` covering `secrets/*.yaml` and `secrets/*.env` — including `encrypted_regex: '.*'`, which matters because SOPS's default policy leaves keys ending in `_unencrypted` in the clear[[getsops](https://getsops.io/docs/reference/)]
- A pre-commit hook that inspects the staged git index (not the working tree), verifies ciphertext cryptographically, and enforces the full-encryption policy from the staged file's own metadata
- Workflow, rotation, and multi-machine portability sections

## Verified behavior

The hook was exercised against an 18-case matrix using the pinned versions, and all cases pass: plaintext, tampered ciphertext, and MAC-valid-but-lax files are all blocked; properly encrypted files (nested paths, spaces in names, dotenv) commit cleanly; and it fails closed when `sops` or a valid key is missing. Testing used the Linux builds of the same versions, so the Big Sur claim rests on toolchain evidence rather than execution on your machine — noted honestly in the guide.
