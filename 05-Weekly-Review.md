# Weekly review index

## Review cadence

Schedule a 30–45 minute review once per week.

The purpose is to prevent research expansion, preserve documentation quality, and keep spending aligned with validated progress.

## Weekly checklist

- [ ] Update task statuses and remove completed items from active lists
- [ ] Record actual compute, storage, API, and annotation costs
- [ ] Review B2 output prefixes and remove only explicitly disposable scratch artifacts
- [ ] Confirm raw masters remain immutable
- [ ] Review rights/consent status for all newly selected clips
- [ ] Add experiment results and links to overlay outputs
- [ ] Add architecture decisions made during the week
- [ ] Add failure modes to the error taxonomy
- [ ] Identify one bottleneck for next week
- [ ] Choose three to five maximum high-priority tasks
- [ ] Confirm no secret, restricted media, or identifying information is in public Git content
- [ ] Update portfolio evidence: screenshots, metrics, before/after examples, implementation notes
